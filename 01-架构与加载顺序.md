# 01 · 架构与加载顺序

## DSH 是什么

一个 Electron 桌面应用 + 一套 **cordis 插件框架**（cordis 是 Koishi 作者的依赖注入/插件框架）。
所有能力——LLM 调用、工具、沙箱、会话存储、UI——都是插件。

- **宿主进程**：`resources\app.asar` 里的 Node 代码
- **浏览器端**：`@deepseek-ai/dsh-client-*` 系列（Web GUI 的 UI 层）
- **配置**：`$DSH_HOME`（默认 `~/.dsh`）下的 profile 目录

---

## 三层结构

```
bundle（包）
  └── patch（YAML 行清单）
        └── plugin（真正的功能插件）
```

**bundle** 是一个 npm 包，它的 `package.json` 里声明：

```json
{
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

或（多文件时）：

```json
{
  "dsh": { "bundle": { "patch": [
    "./cordis.patch.yml",
    "./presets/standard.patch.yml",
    "./presets/ptc.patch.yml",
    "./presets/minimal.patch.yml",
    "./presets/cordis.patch.yml"
  ] } }
}
```

**patch** 是 YAML 数组，每个元素是一行插件声明：

```yaml
- id: agent-instructions                  # 行 id，patch 靠它定位覆盖
  name: '@deepseek-ai/dsh-agent-instructions'   # 插件包名
  config:                                 # 插件配置
    maxBytes: 65536
  disabled: false                         # 可选

- insert:                                 # 也可以批量插入
    - id: timer
      name: '@deepseek-ai/cordis-plugin-timer'
```

支持 `!!js` 表达式，在加载时求值：

```yaml
disabled: !!js "!ctx.get('profileContext')"
mode: !!js process.env.DSH_PERMISSION_MODE ?? 'workspace-write'
```

## patch 加载顺序（关键）

`dsh-app-boot/lib/index.js:1025-1030`，**后者覆盖前者**：

```js
...profile.layers.flatMap(l => l.patches),                                // 1. bundles（base → web-app → peakvalley）
...loadOptionalPatches(binName, context.patchPath),                       // 2. profile 的 cordis.patch.yml
...loadOptionalPatches(binName, join(context.home, "cordis.patch.yml")),  // 3. home 级 cordis.patch.yml
...context.overlays                                                       // 4. --patch 命令行
```

| 层 | 路径 | 优先级 | 现状 |
|---|---|---|---|
| 1 | bundle 内置 patch | 最低 | 只读 |
| 2 | `~/.dsh/profiles/desktop/cordis.patch.yml` | 中 | ✅ **用户权威层** |
| 3 | `~/.dsh/cordis.patch.yml` | **高于第 2 层** | ❌ 不存在 |
| 4 | `--patch <file>` | 最高 | 运行时 |

> ⚠️ 第 3 层是"机器级偏好，对所有 profile 生效"，注释原文：
> *"machine-local preferences that apply to every profile, so it outranks the per-profile layer"*。
> 排障时如果改了 profile 层没反应，先确认这个文件不存在。

**覆盖语义**：patch 是**整行替换 `config`**，不是深合并。所以一行插件如果要改配置，必须重述它拥有的每个键。

## web-app bundle 追加/覆盖的关键行

`dsh-web-app/cordis.patch.yml`（21637 字节，565 行）：

| 行 | 内容 |
|---|---|
| `system-prompt`（L16-20） | 覆盖 persona：`You are a coding agent powered by the {{model}} model.` + `Your working directory is {{cwd}}.` |
| `session-reference`（L94-95） | 跨会话引用 |
| `file-reference-local`（L97-98） | `@` 路径引用 |
| `workspace-changes`（L339-340） | 工作区改动记录（仅客户端可见） |
| `agent-preset-registry`（L561-565） | `default: standard` |

**host plane 与 preset plane 的划分**（L430-556）：
web 层把一批行 `disabled: true` 禁掉，交给 preset 重新挂载——包括
`tool-bash`、`tool-pwsh`、`tool-jobs`、`tool-fs`、`tool-fs-search`、`skill-filesystem`、
`tool-skill`、`command-goal`、`tool-goal`、`plan-mode`、`compaction-basic`、
`command-compact`、`tool-result-pruner`、`tool-subagent*`、`workflow-ptc`、
`tool-workflow`、`tool-ralph`、`agent-instructions`、`tool-todo`、`tool-web`。

理由（注释原文）：注册表（jobs / skills / goals / subagents / token-meter）留在 host plane
是因为它们是进程级单例；每个 agent 的工具与提示词段才进 preset plane。

## profile 目录结构

```
~/.dsh/
├── AGENTS.md                      # 用户全局指令（唯一在用的指令文件）
├── .credentials.yaml              # 凭证
├── .anonymous-user-id             # 遥测匿名 id
├── cordis.patch.yml               # home 层 patch（当前不存在，优先级高于 profile 层）
├── profiles/
│   └── desktop/                   # 当前 profile
│       ├── cordis.yml             # 空根 []，不要编辑
│       ├── cordis.patch.yml       # ★ 用户权威配置层
│       ├── package.json           # bundle 列表
│       ├── pnpm-lock.yaml
│       └── pnpm-workspace.yaml
├── sessions/                      # 会话日志（JSONL）
├── storages/                      # KV 存储（workspace.json 等）
├── skills/                        # 用户级技能（当前不存在）
└── dsh-runtimes/                  # 内置 Node / Python 运行时
```

`cordis.yml` 的注释明说：*"Edit cordis.patch.yml, not this file."*
